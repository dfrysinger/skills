# Cumulative skill hill climb

Improve one published skill across a corpus. A task lane supplies evidence for
the shared draft; it does not own a specialist skill release. The leading
measure is how many previously failed tasks one exact shared revision solves
while retaining its earlier wins. Report pooled passes from different skills,
models, or case revisions separately.

## 1. Start from the published lineage

Name the published skill bytes and the maintained passing tasks before selecting
a previously failed task. Run the published skill on that task under a fixed,
valid contract, or use a completed matching run whose exact inputs remain
applicable. Establish its failure at the product boundary and inspect the
candidate's first wrong decision, existing instructions, and the task's visible
authority. An untested task is **unknown**, not a baseline failure.

Create the first working draft from the published skill. If another task has
already produced an integrated draft, start the next task and all its
experiments from **that draft**, which carries the published rules and the
supported improvements since release. An older, neutral, lean, or no-skill
version may be an explicit control for attribution or ablation, never the new
development starting point. Give each independent investigation its own
isolated copy of this same draft and frozen task inputs.

Complete when the draft's published ancestor, latest integrated parent,
prior-win set, case identity, comparator, and first observable failure are
recorded.

## 2. Search broadly at the current failure frontier

Generate distinct, falsifiable ideas for the earliest wrong decision using
[`parallel treatment search`](parallel-treatment-search.md). A field of around
20 independent ideas is a useful *parallelism target* when the evidence supports
it, not a quota: do not pad it with synonymous wording or weak guesses. Build
as many credible arms as capacity allows concurrently, with each arm changing
one general mechanism relative to the **same accumulating draft**. Predeclare
controls, repetitions, selection, and unchanged task/model/tool/judge inputs.
The published skill remains an additional reference when attribution to the
last release matters. Keep every first outcome; judge native product behavior
and regressions before crediting instruction uptake.

Independent task lanes may search concurrently, but freeze each lane's draft
parent. A treatment selected on one lane is a proposal to integrate, not
evidence that the combined skill retains the other lanes' wins. When a wave
finishes, compare complete outcomes and the candidate decisions that caused
them. Integrate compatible supported tactics into **one** successor draft,
test their interaction on the target, and account for previously passing
tasks they can reach. Do not append every winning sentence: keep only the
general mechanism needed by the combined behavior.

Complete when the successor draft has one exact identity, its changed rules
have evidence, and its target result and affected earlier wins are classified.

## 3. Advance the frontier, not the number of variants

If the successor still fails, inspect the *new* earliest wrong decision.
Search another parallel field from the successor draft, retaining its proven
rules. Never restart from an old control just because the target is still red.
When parallel lanes converge, reconcile their changes before moving the shared
draft again; experiment receipts from distinct drafts do not add up to one
draft's score.

Stop searching on the same frontier when a batch does not move product behavior.
Check whether the limit is skill instruction, model capability, unavailable
task authority, an invalid evaluator, or a runtime/time constraint before
creating more variants. A qualified reference implementation proves the test
can run, not that the model and skill can solve it.

Complete when the draft has a replicated complete task PASS or the blocker is
classified with an explicit revisit condition. An isolated one-off PASS is a
lead, not yet a publishable gain.

## 4. Minimize the new increment

Once the combined draft passes, start a fresh **delta ablation** at the published
skill, not at no skill. Add only the new general sentences or mechanisms needed
to reproduce the gain. Test single additions first; test combinations when
their behavior interacts. Remove instructions whose absence does not reduce
target success or weaken an earlier passing task. Compare the minimal
candidate with the full exploratory draft under the same frozen case, model,
limits, product, and judge contract. Preserve repetitions when outcomes vary;
one lucky run cannot establish that an instruction is unnecessary.

Run the resulting exact candidate against all maintained earlier passing
tasks, including wins from other lanes. If one regresses, diagnose its first
wrong decision and run a new parallel search based on this **same integrated
candidate**; minimize the repair again. Do not silently move an old case's
fixture or switch models to turn a red cell green. Mark cells with unusable or
missing evidence unknown, not pass.

Complete when the smallest supported increment preserves the measured
previous wins and newly conquered task under one exact skill identity.

## 5. Rebuild the whole skill only when warranted

If accumulated procedure appears to dilute or contradict load-bearing rules,
run the full [`ablation campaign`](ablation-campaign.md). Compare neutral,
from-first-principles lean, and unchanged published/full arms on the same
corpus. Build the lean skill back up from the independently demonstrated
behaviors across *all* maintained tasks, not just the newest task. Its lack of
history makes it a diagnostic arm until it reproduces the existing wins.

Complete when the lean replacement's exact bytes, pass distribution, retry
dependence, and lost or retained behaviors have been compared with the
published skill. If it cannot preserve the gains, keep the incremental skill
rather than publishing a shorter regression.

## 6. Publish one shared result and repeat

On the final exact bytes, compare the newly conquered task with the published
baseline under the same contract, verify mechanism uptake and held-out
transfer, protect every maintained passing task, and finish structural checks
and independent review. Use the release rule in `SKILL.md`; do not wait for
every unsolved task. After publication the released bytes become the next
parent and control. Carry remaining failures and the most promising supported
ideas forward, preserving each experimental first result and its original
identity.

Complete when the published skill, installed skill where applicable, target
and earlier-win scorecard all name the same exact revision, with unsolved and
unverified tasks visible rather than pooled into its pass count.
