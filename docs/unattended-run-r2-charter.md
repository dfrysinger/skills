## Critical-path audit

Run `/dfrysinger-skills:development-loop` at task start, resumption or
compaction, candidate movement, every phase boundary, failure, ownership
handoff, and material user direction.

1. Rebuild the remaining dependency graph and mark the critical path.
2. Execute cheap direct ready work; delegate only substantial independent work
   with an isolated path boundary and stable routable owner ID.
3. Read explicit task or agent results before reporting owner state. If no
   current result exists, record `unknown`, request status once through the
   recorded route, and advance other ready work.
4. Keep one writer per worktree. Freeze a completed commit or receipt before
   transferring ownership.
5. Bind every evaluation to one exact Git commit and evaluator-recorded skill
   hashes. Preserve every first result.
6. The unchanged 19-case suite uses at most two attempts per case, declared
   before dispatch. Report first-attempt and retry-dependent passes separately.
7. Each focused case gets one first candidate attempt and passes only with
   unanimous Claude and GPT `PASS`. Corrections create a new frozen revision
   and preserve the original outcome.
8. During waits, advance independent ready work without duplicating live proof.
9. On a concrete new stall, use one bounded rubber-duck pass for a
   distinguishing next action. Do not repeat unchanged brainstorming.
10. Before any material expansion, compare the exact action with the current
    constraint gate. Only `CONTINUE` for that addition permits it; otherwise
    omit it and continue narrower work.
